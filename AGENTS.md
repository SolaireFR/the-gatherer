## **📌 Partie 1 : Comportement de l'Agent**
*Applicable à TOUTES les interactions, quel que soit le projet.*

- **Exécution immédiate** : Tout verbe explicite (MODIFIE, FIX, CRÉE) exige l'édition directe des fichiers sans demander de confirmation.
- **Questions strictement limitées** : Interroge uniquement en cas d'ambiguïté technique, d'info essentielle manquante ou de risque irréversible.
- **Rigueur & Erreurs** : Lis l'intégralité du prompt sans supposer. En cas d'erreur de commande, retente une seule fois avec ajustement avant de remonter le blocage.
- **GIT** : NE TOUCHE JAMAIS à GIT. C'est TOUJOURS moi qui m'en occuperai. Pas de commit, push, revert ou pull. Tu peux juste checker les diffs et anciens commits.
- **⚠️ Documentation des composants (VITAL)** : Uniquement dans le dépôt du moteur (`git remote -v` pointe vers `github.com/SolaireFR/gosvelte`) : toute création/modification d'une brique générique (`gosvelte-core`, `gosvelte-front/src/lib`) DOIT être documentée de facon ultra concise dans la Partie 3 de l'`AGENTS.md` de `gosvelte-template` et dans la même tâche. **Dans un projet dérivé : AUCUNE modification de `AGENTS.md`, sous aucun prétexte.**

## **💻 Partie 2 : Règles de Codage (Tous Projets Confondus)**
*Applicable à TOUS les langages/frameworks, sauf si la Partie 3 l’outrepasse.*

- **Organisation** : Fichiers et dossiers en `kebab-case` (sauf classes en `PascalCase` et constantes en `SCREAMING_SNAKE_CASE`).
- **Code & Typage** : Typage strict obligatoire (interdit `any` et `// @ts-ignore`). Fonctions < 50 lignes (`verbeSujet`, 1 responsabilité). Pas de `if` imbriqués > 2 niveaux.
- **Erreurs** : Capture et logs obligatoires, messages actionnables, codes HTTP standards. Interdit les `try/catch` vides.
- **Sécurité** : Aucun secret en dur (variables d'env), validation/sanitisation des inputs et vérification des permissions côté serveur.
- **GIT** : NE TOUCHE JAMAIS à GIT. C'est TOUJOURS moi qui m'en occuperai.

### Commandes (`go tool gosvelte <commande>` ou `pnpm dev|build|check`, racine du projet ou sous-dossier)
`dev` (génère + Vite :4444 sur localhost + app Go :3333, recompilée à chaque modif de `back/` / `.env`) · `build` (front + robots.txt / sitemap.xml embarqués → `.gosvelte/bin/app[.exe]`) · `start` (build + lance :3333) · `generate` (`.gosvelte/` : env.ts, api.ts, types SvelteKit ; après un clone / pull, pour l'IDE) · `check` (svelte-check + go vet) · `docker [args docker build…]` (image scratch) · `services [up|down]` (MySQL, MinIO, Keycloak de dev, inutiles avec les drivers par défaut sqlite / basic / local) · `mobile [sync|dev|open android|ios|add android|ios]` (`dev` : Vite sur le réseau local) · `update [version]` (moteur local : reconstruit gosvelte-front ; sinon gosvelte-core + gosvelte-front du même commit ; front pas encore publié par la CI = erreur, projet inchangé) · `version` ; hors projet : `new <dossier> [--local <dépôt>]` (`.env` avec `JWT_SECRET_KEY`, `SETTINGS_SECRET_KEY` et `ADMIN_PASSWORD` aléatoires ; sans dépôt local : version publiée, `GOSVELTE_TOKEN` et `GOSVELTE_NPM_TOKEN` requis). `go tool` utilise la version de `go.mod` ; installation globale possible : `go install github.com/SolaireFR/gosvelte/gosvelte-core/cmd/gosvelte@vX.Y.Z`.

### Pièges
- Dépendance npm : `pnpm add <paquet>` à la racine ; outillage (Vite, svelte-check…) fourni par gosvelte-front, ne pas l'ajouter.
- `.gosvelte/` est écrasé : jamais modifié à la main ; `api.ts` / `env.ts` : modifier le Go / `.env` puis `go tool gosvelte generate` (automatique dans `pnpm dev`).
- Dépendance Go : `go get …` à la racine (`go.mod`).
- Projet sur versions publiées (dépôt privé) : `GOSVELTE_TOKEN` (jeton fine-grained, dépôt SolaireFR/gosvelte, Contents en lecture : template, modules Go), `GOSVELTE_NPM_TOKEN` (jeton classic `read:packages` : gosvelte-front) et `GOPRIVATE=github.com/SolaireFR/*` dans l'environnement (et en secrets de CI)  ; `.npmrc` du projet = registre de gosvelte-front seul (pnpm ignore les identifiants d'un `.npmrc` de projet) ; authentification dans `~/.npmrc` (`//npm.pkg.github.com/:_authToken=${GOSVELTE_NPM_TOKEN}`, ajoutée par `gosvelte`).
- App mobile : ajouter `@capacitor/cli`, `@capacitor/core` et `@capacitor/android` / `@capacitor/ios` au `package.json` avant `gosvelte mobile`.
- Changement de driver / provider / stockage dans `back/main.go` → `go mod tidy` (`gosvelte dev` le relance seul sur « missing go.sum entry »).
- `gosvelte docker` grave dans le front les `PUBLIC_*` de `.env.example` (pas de `.env`) ; les autres variables se passent au conteneur.
- `src/lib/theme.css` et `src/lib/changelog.md` optionnels : après en avoir créé ou supprimé un, relancer `pnpm dev`.
- En dev, ouvrir :4444 (Vite) : :3333 (API) répond « Front non construit » sur les pages.
- Ne jamais créer `back/gosvelte-front/` ni `back/zz_gosvelte_front.go` : noms réservés à l'overlay du build.
- Route GET : jamais de modification (protection CSRF limitée à POST / PUT / PATCH / DELETE).
- Masquer un bouton ne protège rien : `auth.Require()` sur la route Go ; données d'un utilisateur : propriétaire vérifié dans le handler (`server.User`, modèle `writableVoiture` de `back/example/voiture.go`), sinon tout inscrit modifie tout.
- Valeurs publiques de `.env.example` (`JWT_SECRET_KEY`, `SETTINGS_SECRET_KEY`, `ADMIN_PASSWORD`) refusées hors `gosvelte dev` (binaire, `start`, Docker) : `gosvelte new` en génère d'aléatoires dans `.env`.
- Route cachée (modèle : `/api/admin`) : jamais `auth.Require` (ses 401 / 403 révèlent la route) mais `server.NotFound(w)`, `auth.MayHaveRole` avant `auth.CurrentUser` (refus sans réseau ni base), aucun en-tête avant la décision, pas de motif finissant par `/` ou `{x...}` (redirection 307 révélatrice).
- Secret modifiable à chaud (clé d'API…) : `settings.Secret`, jamais renvoyé au navigateur ; réglage lu par `.Get()` à chaque usage, jamais copié dans une variable au démarrage (modification sinon sans effet).
- Aucune ligne `[public]` de changelog sur la page /admin (lue par tous : la révèle).
- Keycloak : nombre de sessions du tableau de bord = rôle `view-clients` (realm-management) du compte de service `KEYCLOAK_ADMIN_CLIENT_ID` (realm déjà importé : rôle à ajouter à la main).
- Jamais `os.Open` depuis un paramètre de requête (lecture de `.env`) : fichiers = `storage`.
- Images : jamais l'original dans `<img>` → `thumbUrl(file)` / `fileLink(id, 'preview')` ; gros fichiers via `fileLink` / `downloadFile`, pas `fetchFile`.
- Deux drivers DB, providers d'auth ou stockages importés → `panic` au démarrage.

### Maintenir le moteur (dépôt gosvelte uniquement : README-local.md)
- **Tester** : `gosvelte dev-gs` (dépôt gosvelte UNIQUEMENT, erreur ailleurs) : `example/` régénéré depuis `gosvelte-template` + sources locales (`example/data` conservé, `.env` recréé depuis `.env.example`), puis `gosvelte dev` ; avertit si la commande installée est plus ancienne que `cmd/gosvelte` / `internal/` (réinstaller : `go -C gosvelte-core install ./cmd/gosvelte`).
- **Où** : CLI `gosvelte-core/cmd/gosvelte` (`new` copie `gosvelte-template/`) (gabarits embarqués `cmd/gosvelte/templates/` dont `front.go.tmpl` = fichier de l'overlay, générateurs `internal/apigen` et `internal/envgen`) ; presets SvelteKit / Vite / SEO `gosvelte-front/presets/`.
- **Compatibilité** : versions semver alignées : tag `vX.Y.Z` de gosvelte-core (Go + CLI) = `version` npm de gosvelte-front (le projet requiert les deux à la même version) ; tout ajout est optionnel (absent = comportement d'avant) ; ne jamais supprimer ni renommer une clé, prop, type, icône, variable CSS, package, export, commande ou fichier de `.gosvelte/` sans version majeure : sinon `@deprecated` + alias.
- **Changelog** : `gosvelte-core/CHANGELOG.md` et `gosvelte-front/src/lib/CHANGELOG.md` (lignes `[public]` affichées par « Nouveautés ») ; format `## AAAA-MM-JJ` puis `- item`. `src/lib/changelog.md` = changelog du projet dérivé.
